# GUIDE fold + HUD strip removal — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The six-arrow-deep MENU (PLAY, LEVEL SELECT, OPTIONS, HOW TO PLAY,
ITEMS, ENEMIES, HIGH SCORES, SOURCE — 8 rows) becomes six rows, with a new
`GUIDE` sub-page holding the three help screens one hop deeper. The
duplicate HTML `#hud` strip — four of its six facts already painted by the
canvas HUD row — is deleted outright; its two unique facts (`LV`,
`ENEMIES` remaining) migrate into that canvas row as two more chips beside
BOMB/FLAME.

**Architecture:** `SCREEN.GUIDE = 11` is **appended** after
`SETTINGS:10`, following the exact append-only discipline `SETTINGS` itself
established — never inserted, or every later frozen value shifts.
`SCREEN.HOWTO`/`ITEMS`/`ENEMIES` keep their existing values and draw
functions untouched; only their entry point moves from MENU to GUIDE, and
their `back()` target moves from MENU to GUIDE with them. GUIDE is
navigationally a second flat list — its own cursor (`app.guideRow`), same
wrap-both-directions `move()`/`update()`/`_tapMove()` shape MENU already
has, no knob machinery, no dedicated touch hit-test (MENU has none either;
see spec §2). The HUD strip removal is a pure subtraction on the HTML/JS
side plus a small addition to the canvas `drawHudChips` chip row that
already exists — no new screens, no new state.

**Tech Stack:** Pure ES modules, `node --test` / `tests/*.test.mjs`,
Canvas 2D. Zero npm runtime deps. `menudraw.js` must not import from
`src/app/`; `shellview.js` is the only render module that may read
`src/app/`.

**Spec:** `docs/superpowers/specs/2026-09-05-guide-hud-design.md`

**Depends on:** nothing new — S1/S2/S3 (settings store, OPTIONS screen,
pause menu + prior chrome removal) are already shipped and untouched here.

## Global Constraints

- `SCREEN.GUIDE = 11`, **appended after `SETTINGS:10`**. Inserting shifts
  no later value today (SETTINGS is currently the last), but the discipline
  is load-bearing precedent — do not renumber `SETTINGS`.
- `ITEMS` is frozen at exactly 6 entries in the spec's order:
  `PLAY, LEVEL SELECT, OPTIONS, GUIDE, HIGH SCORES, SOURCE`. `OPTIONS`
  **keeps cursor index 2** — it does not move.
- `SCREEN.HOWTO`, `SCREEN.ITEMS`, `SCREEN.ENEMIES` are **not renamed and do
  not change value**. Their draw functions and existing tests are
  untouched except for their `back()` target.
- GUIDE reuses MENU's navigation shape exactly (own cursor, wraps both
  ways, no axis split) — not SETTINGS' `move(dir,axis)` knob shape. No new
  `guideHit` touch helper: GUIDE inherits the same tap-confirms-current-row
  fallback MENU and every read-only subscreen already use in
  `shellview.js`/`main.js`.
- GUIDE does **not** join `SCREEN.MENU`'s idle→ATTRACT accumulation — like
  every other subscreen, it resets `idleT` to 0 every frame.
- No comments unless the file already uses explanatory block comments (its
  style). `menuapp.js`, `menudraw.js`, `scenes.js` and `shellview.js` all
  do.
- Never write the banned grid-bomb franchise name into any committed file.
- PWA: bump `CACHE_NAME` (`src/pwa/shell.js:1`) and `REV` (`sw.js:3`)
  **together**, `current vN → vN+1`, in every commit here — every touched
  file (`menuapp.js`, `menudraw.js`, `shellview.js`, `scenes.js`,
  `main.js`, `index.html`) is in `PRECACHE`/`SRC`. **Read the current value
  first** — concurrent sessions bump the same two lines.
- The `drawHudChips`/`chip()` edits in Task 3 must not change BOMB/FLAME's
  existing pixels (same `x`, `w`, icon, label, count) — only add two more
  chips after FLAME. Any test asserting `BOMB`/`FLAME`/heart output today
  must still pass byte-for-byte.

**3a — `src/render/menudraw.js`.** Append after `drawEnemiesHelp` (before
the `PLAQUE_NAME` comment):

```js
/* GUIDE (folds HOW TO PLAY / ITEMS / ENEMIES one hop under MENU): a plain
   3-row list navigated exactly like MENU — own cursor, wraps both ways, tap
   confirms the row under the cursor. Not the SETTINGS knob model: these
   rows are doors to open, not values to adjust, so there is no value
   column and no dedicated hit-test (spec §2 — MENU has none either). */
const GUIDE_LABEL = ["HOW TO PLAY", "ITEMS", "ENEMIES"];
export function guideGeom(L) {
  const S = shellBox(L, 480);
  const y0 = S.headY + 26,
    y1 = S.footY - 14;
  return { S, y0, rowH: (y1 - y0) / 3 };
}
export function drawGuide(c, L, t, cursor) {
  const cur = cursor | 0;
  const S = shell(c, L, 480);
  head(c, S, "GUIDE", "HOW TO · ITEMS · ENEMIES");
  const g = guideGeom(L);
  for (let i = 0; i < 3; i++) {
    const y = g.y0 + i * g.rowH + g.rowH / 2;
    const sel = i === cur;
    if (sel) {
      c.fillStyle = "rgba(55,240,208,0.14)";
      c.fillRect(S.ix, y - g.rowH / 2 + 2, S.iw, g.rowH - 4);
      c.fillStyle = ACCENT;
      c.fillRect(S.ix, y - g.rowH / 2 + 2, 3, g.rowH - 4);
      caret(c, S.ix + 8, y, g.rowH - 4);
    }
    c.textAlign = "left";
    c.textBaseline = "middle";
    c.font = font(14, sel ? "900" : "");
    c.fillStyle = sel ? TEXT : MUTED;
    c.fillText(GUIDE_LABEL[i], S.ix + 22, y);
  }
  foot(c, S, "↑↓ ROW · ENTER OPEN · ESC BACK");
}
```
