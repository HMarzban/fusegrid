# Art Acceptance + Media Recapture (P5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the whole pass actually landed on screen — not in a green battery — then recapture every committed still so the shipped listing art shows the game that now exists.

**Architecture:** Node cannot render pixels, so P1–P4's green suites are necessary and not sufficient. The 2026-09-04 record already contains one "mature silhouettes" commit that never changed the picture. This plan is the mandatory headed screenshot-critique loop across every surface, then a live recapture in place of `og.png`, the cover, four stills and the GIF, then the provenance updates that keep `media/README.md` and `AGENTS.md` honest about how those bytes were made.

**Tech Stack:** Loopback `node serve.js`, a headed browser, the in-page capture script `e2e-artifacts/capture/card.js` (gitignored tooling, never shipped, never committed). `node --test` for the dimension gates.

**Spec:** `docs/superpowers/specs/2026-09-05-items-player-art-design.md`

## Global Constraints

- **Before any capture:** unregister the service worker and delete its caches. A stale SW serves pre-change bytes and is indistinguishable from a render change that did not land. This is not optional and it is not a one-time step — redo it after every source fix.
- Do not declare done while any acceptance line fails. The loop is implement → capture → score every line → fix → recapture.
- Fixes arising from the loop are **art only**: shape, value, animation. No `src/core` edit, no hue move, no AI retune, no `CFG` change, no per-biome camera / light / entity table. If items die in VOID, that is a finding for this loop, not a pre-locked emissive value — VOID's darkness is albedo and one global recipe preserves it.
- `tests/media.test.mjs` takes **zero edits**: `og.png` stays 1200×630, `media/cover-630x500.png` stays exactly 630×500, and the four stills plus `play.gif` stay present. Recapture **in place** — never crop one asset out of another.
- The hero stays a REAL screenshot of the live 3D board — never generated key art, which drifts from the game.
- `og:image` stays the absolute Pages URL. `og.png` stays **out** of the PWA precache, and `media/` is never staged for Pages.
- The Social-preview upload in repo Settings has no API — it is a manual step, recorded as a checkbox, not automated.
- Never write the banned grid-bomb franchise name on the image, in alt text, in tags, or in any committed file.
- Do not commit `.cursor/` or `e2e-artifacts/` — both are gitignored.
- PWA: bump `CACHE_NAME` (`src/pwa/shell.js:1`) and `REV` (`sw.js:3`) **together**, `current vN → vN+1`, **only** if a fix in Task 1 changes bytes listed in `shell.js`'s `SRC`. Tasks 2 and 3 touch only `media/`, `og.png`, `AGENTS.md` and `MEMORY.md`, none of which are precached — no bump there.

- [ ] **Step 2: Score every acceptance line — this is the RED step**

Write a pass/fail beside each line. Expect failures on the first round; that is the point of the loop.

- [ ] 1. From the frozen rig at two tiles' distance, no two of the 12 pickups share a plan-view outline
- [ ] 2. Every pickup reads as hovering — a visible gap and a separate cast shadow — not as a decal painted on the floor. The flat families are the risk here
- [ ] 3. Family is readable from the ring alone: hairline / double / dashed / spiked
- [ ] 4. The four idle rhythms are distinguishable when two families sit side by side
- [ ] 5. **The player is not mistaken for WALKER at two tiles.** If it fails, the fix is shape and value structure, never hue
- [ ] 6. The crown carries `p.color` and nothing else on the player does
- [ ] 7. Exactly one specular highlight on the player (the visor). The hull reads matte
- [ ] 8. No antenna, no ball, no round double eyes, in either renderer, anywhere, including the ENEMIES / ITEMS plates and the attract loop
- [ ] 9. Walking up-screen shows the nape, not the visor, in CLASSIC 2D
- [ ] 10. Items stay legible in VOID with no per-biome table
- [ ] 11. ITEMS well at 16px and HUD chips at 14px: all 12 glyphs still separable
- [ ] 12. The touch bomb pad still reads as BOMB
- [ ] 13. Both renderers agree on the story: the notch / point / tier count a kind shows in 2D is the count it shows in 3D

Watch the named risk pair specifically: `bomb` (spinning 4-gon, `maxR 10`) against `power` (spinning 4-fold cross, `maxR 11`). They separate on **height** — a 15.6-tall upright shard against a ~7-tall flat plate — and on the family ring. If any pair is confusable at two tiles, it will be this one.

- [ ] **Step 3: Fix, unregister the SW again, recapture, rescore**

Art-only fixes, in the plan the finding belongs to:

- a colliding plan-view footprint → adjust the smaller kind's `r` by `±0.01 * CFG.TILE` in `ITEM_MAKE` (spec §4.17's only sanctioned remedy)
- a glyph illegible at `0.41×` → simplify its `ITEM_SHAPE` outline or enlarge its `ITEM_ACCENT`; the outline budget stays `<= 12` verts and the accent stays `<= 3` solid ops
- a pickup reading as a floor decal → raise the family's idle `y` base, never add a mesh
- the hero still reading as WALKER → widen the yoke or deepen the boot value; **never** touch `p.color`

- [ ] **Step 4: Re-run the battery after every fix**

Expected: green. Every gate P1–P4 installed still holds — in particular the plan-view distinctness gate, the `<= 12` vertex budget, the `±1.20*s` chip fit, the zero-arc rule, the one-placement `p.color` rule, and fat-world `=== 141`.
