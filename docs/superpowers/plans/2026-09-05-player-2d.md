> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `drawPlayerBody` is built to `enemybody.js`'s standard — silhouette, face, shading, facing, grounding — and stops reading as a toy and as WALKER. The antenna, the antenna ball, the two round cyan eyes and the balloon dome are deleted outright.

**Architecture:** One kite silhouette (`S_RUNNER`), widest at a two-chip shoulder yoke, run through the same three-pass shell the foes use: dark contour, inset lit body lifted so the leftover crescent is the form shadow, upper-left sheen. The separation from WALKER is **structure and value**, never hue: the player becomes the only body on the board with a light matte hull carrying dark parts against a cast where every foe is one saturated hue. `p.color` moves off the torso and the head band and lands on the crown, and only the crown — the largest surface visible from directly above.

**Tech Stack:** Pure ES modules, `node --test` / `tests/*.test.mjs`, Canvas 2D. Zero npm runtime deps.

## Global Constraints

- `createPlayer` numeric fields and `p.color = "#37f0d0"` are untouched. The player / WALKER collision is fixed by structure, not by re-tinting the hero — a colour edit in `src/core` would make this pass non-art.
- **Deleted outright, in both renderers, never reintroduced:** the antenna rod, the antenna ball, the two round cyan eyes, the balloon dome.
- **The zero-arc rule.** With `p.shield` and `p.passing` both false, `drawPlayerBody` emits **zero `arc` ops**. The contact shade is an `ellipse`, the visor core is a rect, the specular pip is a quad. The two status rings are the only arcs the function may ever draw.
- `p.shield` cyan ring, `p.kick` cleats, `p.passing` green ring, the iFrames alpha flicker and the walk/idle bob are **unchanged** — already parity-correct and orthogonal to the hull. `p.kick` does **both**: it flips the boot fill (beat 6) and still paints the cleats.
- Beat 1's contact ellipse uses §2.2's own numbers (`ellipse(0, r*0.98, r*0.72, r*0.20)`); do **not** substitute `enemybody.js`'s `contact()` helper, whose `r*0.86` / `r*0.17` would shift the fit envelope.
- No `fillText` in `drawPlayerBody`, ever.
- `tests/pickups.test.mjs`, `menudraw.test.mjs`, `touch.test.mjs`, `r3d.test.mjs`, `media.test.mjs`, `enemies-art.test.mjs`, `pickup-3d.test.mjs` all stay green with zero edits.
- `textures.js`'s `atlasSources` calls `drawPlayerBody` with a bare `{face:{x:0,y:0},iFrames:0,walk:0,...}` and **no `color`** — keep the `p.color || "#37f0d0"` fallback or the atlas capture throws.
- No comments unless the file already uses explanatory block comments (its style). `sprites.js` does.
- Never write the banned grid-bomb franchise name into any committed file.
- PWA: bump `CACHE_NAME` (`src/pwa/shell.js:1`) and `REV` (`sw.js:3`) **together**, `current vN → vN+1`, in both commits here.

**One resolved spec ambiguity:** §4.13 asks for "nothing paints outside `±1.05r` horizontally / `±1.10r` vertically", but §2.2's own beat-1 ellipse reaches `r*0.98 + r*0.20 = 1.18r` by construction. Both numbers are spec, so the gate splits: everything stays inside `±1.05r` horizontally and `±1.20r` vertically, and **nothing but the contact shade** passes `±1.10r` vertically. Neither authored number is changed.
