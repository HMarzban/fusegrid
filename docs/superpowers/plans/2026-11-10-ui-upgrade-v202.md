# UI upgrade (world + arcade kit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the CONSOLE PANEL menus, PAUSE, WIN/LOSE overlay, CONTROLS drawings, HUD and the FUSE/GRID wordmark with the owner-approved round 5–7 design, in all three looks, without changing the sim.

**Architecture:** The mock-ups are HTML/CSS drawn for the whole browser window; the game draws menus on canvas. The design is ported once as canvas painters in `src/render/kit/` (world tokens, key/well/wall/brick painters, focus, type, custom parts, an offscreen layer cache). Menus and the WIN/LOSE screens move to one full-window canvas (`#sh`, today used only on touch-portrait phones) on every layout; PAUSE stays on the board overlay. Screens move onto the kit one phase at a time, shipped in four releases. Player words move to one render-side table; stores keep their keys.

**Tech Stack:** Pure ES modules, Canvas 2D, `node --test`, headless Chrome via `tools/pixel/shot.mjs` helpers (layout and gates only), headed real-GPU Chrome via `tools/perf/frames.mjs` (frame cost). Zero npm deps.

**Spec:** `docs/superpowers/specs/2026-11-10-ui-upgrade-v202-design.md` and its tracked numbers appendix `docs/superpowers/specs/2026-11-10-ui-upgrade-v202-tables.md` (created in Task 0.2). Visual reference (git-ignored, local only, never read by a test): `.superpowers/sdd/notes/v202-ui-upgrade/` — kit `round7/K7-kit/`, screens `round7/{S7-menu,S7-pages,E7-end,C7-controls,L7-logo}`, art notes `round6/art/*.md`, `round7/art/logo-b.md`, PNGs in each `png/`, each lane's `notes.md` "New parts". Plan reviews: `.superpowers/sdd/notes/v202-ui-upgrade/plan-review/{hoe,staff-code,staff-render,art,qa}.md`.

## Global Constraints

- **Start:** the owner squash-releases `feature/delivery` onto `main` (one neutral commit; it is shell v202). Branch `feature/ui-upgrade` from that commit. Only Tasks 0.2, 1.1 and 1.3 (new files only) may start on `feature/delivery`'s head and rebase onto the squash; every other task waits for the squash, because delivery changes `main.js`, `menuapp.js`, `menudraw.js`, `scenes.js`, `shellview.js`, `index.html`, the loadbar pins and their tests. Never push; the owner pushes. Shell numbers for this work are v203+ (R1..R4 below).
- **Sim:** no behavioural change to `src/core`, `src/ai`, stores' keys, bits or indices (`nb.pact.v1`, heat 0..2, pace -1..1, medal bits). Two display-string edits in core are allowed by ruling (R6): `POWER[].name`/`.help` in `src/core/entities.js` and the `tileTip` copy in `src/core/feat.js`; `tests/determinism.test.mjs` must stay green.
- Zero npm dependencies; no downloaded font: display text is `900 Npx system-ui,-apple-system,'Segoe UI',Roboto,sans-serif`; labels 700 on the same stack; no monospace for words.
- `SCREEN` values are appended, never inserted; this plan adds none. `menudraw.js` never imports `src/app`; `hudart.js` imports nothing; `main.js` stays `<= 799` lines with no inline `import()`; no `src/render/kit/**` or page module imports `board3.js`.
- PIXEL code never imports `vendor/three.module.js` or `render/three`; the px lazy tree stays under 192 KB (166.0 KB today); the PIXEL logo gets at most 8 KB of it. `three/wrapper.js` never imports `logo/`.
- **Focus:** the bomb BODY (`drawBombBody(..., {bare:true})`, R8) at the row start + the row band; a focused key also gets a 3 px cream ring offset 3 px. No cord, no spark, no burning fuse as a marker anywhere. The logo's own cord is the exception.
- Yellow `#ffd447` fills at most one part per screen. Coral `#ff5d73` danger only. Cream ink `#fff2df`. State lightness pinned per world via `toL` (table in the appendix); ICE UI hue `TINT.ICE`.
- **No filters:** no `ctx.filter`, `shadowBlur`, `shadowColor`, CSS `filter` or `backdrop-filter` on `#c`, `#sh`, `#px`, `#gl`; drops are hard offset fills. No `getImageData`/`toDataURL` in any paint path.
- **Frame cost (R16, R23):** static parts are drawn into offscreen layers (`kit/cache.js`) and blitted; a steady menu frame makes <= 400 canvas calls, <= 20 `measureText`, 0 cache misses; a cold world fill <= 16 ms on the desk machine; phone layers at backing dpr <= 2, total <= 24 MB, freed 10 s after leaving shell screens and on `pagehide`. Measured budgets (headed Chrome, `frames.mjs`): menu work p90 <= 2 ms desk, <= 5 ms at `--throttle 4`, 0 long frames >= 50 ms on any page open or room change, menu CPU within +15 % of the v202 baseline.
- **Boot budget (R20):** net boot-graph growth <= +60 KB raw per release after the replaced painters are deleted in the same commit. Boot: kit core, MENU, LEVEL SELECT, PAUSE, the CLASSIC logo. Lazy behind `lazyload.js` like CONTROLS, preloaded in idle: RECORDS, GUIDE, SETTINGS/GRAPHICS, WIN/GAME OVER, `logo/draw3d.js` (with the 3D look), the PIXEL logo (inside the px tree). `tests/loadbar.test.mjs` re-pinned (`--write`) in every task that adds or moves a module.
- Readability gates on every new screen (numbers in the appendix): chosen vs unchosen >= 3:1 greyscale at half size, focus band >= 1.5, ring >= 3:1, cap heights desktop >= 14/11/HUD 18 px, phone >= 11/9, information contrast >= 4.5:1 (locked 3:1) incl. over the world, touch >= 44 px with >= 8 px gaps, every longest string drawn whole (no "…") at text scale 1 and 1.25. Each gate is labelled **Node** (token math or the recorder, in `npm test`) or **Chrome** (`tools/ui/gates.mjs` on captures); the Node twins of one-yellow, ring, 44 px and inside-plate run in every page test.
- Every key reads label first, keycap last. Copy rules: finale WIN goes to MENU; GAME OVER says the shortfall plainly comparing saved to saved (score × difficulty shown); any claim follows "a delta that cannot lie" (`isRunEnd`, run-start `bestRun`); never promise.
- Never name the private reference game; no console maker's name, shape or button symbols; "controller", never "pad", in player copy. When porting mock comments, grep for both.
- CLASSIC call-log hashes (`9fb48f0a:72431`, `7e57d1aa:71503`) cover PLAY + HUD; they move only in Phase 8 (the HUD words included, R9), re-pinned by ruling with the raw call-log diff in the commit body.
- AGENTS.md is updated in the task that changes a fact it states (menu rows, OPTIONS rows, names, PAUSE rows, kit rules), not at release. A dated `MEMORY.md` line after each task.
- Renegotiated tests change strings, labels or geometry only; a reviewer checks that no assertion is weakened.
