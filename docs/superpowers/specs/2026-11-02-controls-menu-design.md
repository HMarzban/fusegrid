## Rulings where the specialists disagreed

| Question | Ruling | Why |
|---|---|---|
| Capture countdown | None | The game is not running; a timer protects nothing and punishes slow players (WCAG 2.2.1). ESC or START cancels, the current button keeps it, a tap off the plate cancels |
| Listening state | Static, no pulse | An endless pulse on an untimed state breaks 2.2.2. The fuse is lit and still |
| Keyboard THROW | E | No action may need two keys at once. The old chord keeps working |
| Rumble default | OFF | Owner may veto. Independent of REDUCE FLASH |
| Controller CONFIRM, BACK | Fixed | Rebinding can never lock a pad-only player out |
| Deadzone | 25%, range 5–60% | Menus read the stick at max(deadzone, 0.50), so drift cannot run the cursor away |
| Stick choice | L or R on the MOVE row | A right-hand path; a full LEFT HAND / RIGHT HAND preset row is left for later |
| Hint word | CONFIRM, not SELECT | A controller has a button called SELECT. Changes `ENTER SELECT` in the MENU and PAUSE cues at build |

## Rules

- **Conflict swaps**, within one device, including keys held by MOVE. One line names both: `EAST WAS REMOTE · REMOTE NOW SOUTH`, and the displaced row reads SWAPPED.
- **Capture arms after 200 ms** and only once the opening press is released, so a double tap cannot bind.
- **Refused keys:** ESC, ENTER, NUMPAD ENTER, BACKSPACE, ARROWS, TAB, F-keys, modifier and lock keys, M R T C B U Y N, 1–5 and NUMPAD 1–5, `[ ]`. Each refusal says why. Sticks, D-PAD and START never bind.
- **Store:** `nb.controls.v1`, on the reset KEEP list; `tests/reset.test.mjs` must be renegotiated.
- **The sim never knows a pad exists.** The pad is another writer into `Input`, with its own held axes and latches, OR-merged with keys. No new wire field.
- **Stick:** radial deadzone, 4-way by dominant axis with 1.25x hysteresis, full speed past the deadzone. No fire buffering; a press holds for one tick so a fast tap cannot fall between ticks.
- **Disconnect:** auto-pause only if the pad was last used and the world is PLAY, kicker `CONTROLLER LOST`. Never auto-resume.
- **Hints follow the last-used device**, flipped by a real press only, 0.75 s dwell. Every glyph has its word beside it. Every prompt composes from live binds: `POWER[].help`, coach, HOW TO, PAUSE cue, OPTIONS note.
- **Accessibility:** inside a selected band text is `#dfe7f5`, never muted (4.13:1 fails). Fixed rows take a padlock and are not dimmed. States carry a shape and a word as well as a colour, since accent and danger bands nearly merge under colour-vision loss. One polite live region for this page only.

## What the build must handle in today's code

1. **A pad alone cannot leave the title.** It advances on DOM events only. Chrome reportedly grants activation on a pad press, Firefox probably, Safari reportedly not; none of it tested here. Design: one pad press always starts the show, silently if the audio context will not run, and music joins on a later key or tap. Check it in headed Chrome first.
2. **THROW without the power plants a bomb at your feet** (`sim.js:174-185`). A one-key THROW must be gated on `players[0].throw`. `pulseThrow` is also a no-op while fire is held (`input.js:108`), so a thumb roll needs handling.
3. **Poll on every rAF above the frame gate.** The idle floor of 20 fps can miss a tap. A pad press must also zero `idleT` and `parked`.
4. **Capture must run before everything:** `input.js` fires `onPause` before `onUiKey`, and `#ana` and `#upd` have their own listeners.
5. **`pauseBack` is linear,** so `pauseView 3` needs its own branch. `update()` needs CONTROLS in its lateral branch.
6. **Twelve OPTIONS rows do not fit at today's pitch.** Keyboard pitch 27 with the note line removed (324 of 330.8); touch pitch 34 unless the shell box fits 37. Row-index literals in `menuapp.test` and `menudraw.test` move.
7. **Key copy is hard-coded** in `input.js` and `menuapp.key()` (WASD taps); both must read the binds.

Disclosed, not fixed by this design: keyboard diagonals move about 1.41x on open floor while a pad is 4-way (changing keys would alter feel and old bests). A pad has no route to the STATS wipe, the camera reset or the consent card, on purpose, so the consent card stays up for a pad-only player and nothing is sent. `menudraw.js:1517` still draws a `K` key cap in a GUIDE preview although `KeyK` is unbound; a live bug found in passing.

## Owner calls

- Pad name: print the device's id (it may carry a maker's name), or always `CONTROLLER 1 · STANDARD`.
- Rumble default OFF.
- Position words SOUTH / EAST / WEST / NORTH, against plainer BOTTOM / RIGHT / LEFT / TOP. The glyph shows the position in both cases.
- The fuse on the pad and on the selection ring (veto: a plain plate and a plain ring).
- A `MOVE STYLE: HOLD / TAP TO WALK` row and LEFT HAND / RIGHT HAND presets: accessibility asks for them, and they are new behaviour, so they are out of this design until decided.
